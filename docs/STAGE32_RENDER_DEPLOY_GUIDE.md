# STAGE32 — Page Check deployment scaffold (Render + Neon)

## Status: configuration ready for review; PUBLIC AUDIT DEPLOY IS STILL BLOCKED

This is NOT a claim that Page Check can safely scan arbitrary public URLs in production.
The current application intentionally refuses live audits when `PAGECHECK_ENV=production`.
That gate has **not** been bypassed, and must not be changed to `development` on Render.
A release requires a separate scanner security milestone with network egress isolation
for Chromium, per-user quotas, admission control, bounded concurrency, a security
review of URL redirects and network destinations, and a public multi-user E2E test.
The Streamlit interface can serve saved/imported reports in production, but the
**Audit page** button remains disabled until those controls exist.

## Architecture

- `pagecheck-ui`: public Render Web Service running Streamlit (paid 0.5 CPU/512MB plan).
- `pagecheck-api`: Render Private Service running FastAPI (paid 1 CPU/2GB plan).
- `pagecheck-expired-audit-cleanup`: hourly Render Cron job, using the UI image.
- PostgreSQL **Neon**: already created independently; it is NOT provisioned by this Blueprint.

All three Render resources are in **Ohio**, matching the selected Neon US East 2 region.
This reduces distance but does not guarantee latency or reliability. The API's
internal hostname is given to Streamlit via a Render `fromService: hostport`
reference. The API does not have a public URL.

## Secrets and cost review

The API's `PAGECHECK_PRIVATE_API_KEY` is generated by Render and passed to
Streamlit by internal service reference. Its value must never appear in a
browser, public log, repo, screenshot, or ZIP. The Neon pooled PostgreSQL
connection string must be supplied twice in Render's secret configuration:
`PAGECHECK_DATABASE_URL` for the **private API** and the **cleanup cron**.
Paste it only in Render's dashboard, **not** into `render.yaml` or a commit.

**This is not a free stack:** the Blueprint includes paid web/private services
and a usage-billed cron job. Render prices and resource limits can change:
review the exact cost estimate *before* approving a Blueprint sync. Chromium
might require more than 2 GB RAM during certain audits; resource sufficiency
has not been proven on Render.

## Build and startup

- `deploy/Dockerfile.api` installs the project and pinned Playwright 1.57.0,
  then installs Chromium system dependencies and browser binaries. NOTE:
  Playwright has not yet been added to the project's `uv.lock`, because lock
  regeneration was not available in the offline preparation environment.
  Reconcile this before full production release.
- `deploy/Dockerfile.ui` installs the locked project dependencies for Streamlit.
- `deploy/start_streamlit.sh` constructs an internal `PAGECHECK_API_URL` from
  `PAGECHECK_API_HOSTPORT`; the value is not exposed client-side.
- `deploy/run_cleanup.sh` performs the existing 24h expiration cleanup.
- The API uses one Uvicorn worker to avoid uncontrolled local browser resource
  multiplication. This is not an abuse-control substitute.

## Local review before any release

1. Extract the STAGE32 patch into a clean local checkout after the latest commit.
2. Run `uv run pytest -q` and `uv run python scripts/render_deploy_preflight.py`.
3. Review `git diff`, then create **a local-only Git commit**. No push yet.
4. Optionally run Docker builds locally when Docker Desktop is available:

   ```powershell
   docker build -f deploy/Dockerfile.ui -t pagecheck-ui:stage32 .
   docker build -f deploy/Dockerfile.api -t pagecheck-api:stage32 .
   ```

5. Do NOT provision paid resources or publish until the security gate, image build,
   migration and end-to-end communication have been validated.

## Later deployment sequence (NOT EXECUTED)

1. User chooses to push a final, audited Git version (repo may be private).
2. On Render, create a **Blueprint** from that repository; inspect paid service
   estimates before approval.
3. Enter the Neon URL in the API and Cron secret fields; don't paste credentials
   in chat or source files.
4. Run `python scripts/postgres_temporary_migrate.py` on a trusted private
   environment with `PAGECHECK_DATABASE_URL` set (schema migration is idempotent).
5. Verify API private TCP readiness and `/health` from Streamlit via Tools.
6. Verify recovery/save/restore and both screenshot sizes from the separate
   containers using synthetic test data. Confirm secrets are not logged.
7. Verify cron deletion of expired records and screenshot cascading deletes.
8. Only after network isolation and abuse controls have passed testing,
   enable public auditing through a separately reviewed production code path.

## Data and output guarantees

- A report is recoverable for **24 hours**. Expired rows may remain in Neon
  until the next hourly cleanup (approximately up to another hour), but cannot
  be restored after expiry.
- PNGs are read by the private API and transferred to the Streamlit server
  via authenticated POST routes. Render services do not share local files.
- Cleanup runs hourly in UTC and deletes expired audit rows, with screenshots
  removed by `ON DELETE CASCADE`.
- No production-enabled Lighthouse/axe-core/Impeccable claim has been made.

## Known limitations

- Container builds have not been validated with Docker here.
- Browser binary availability and memory limits must be tested on Render.
- Public auditing intentionally remains disabled in production.
- A separate credentialed production smoke test is still necessary.
- The existing Starlette TestClient deprecation warning can be cleaned up later.
